## [0.2.0] - 2026-06-26

### Changed — Hybrid Backend Architecture

**Model lineup completely revised.** Four decommissioned Groq models replaced with six actively-served models across two backends:

#### Groq Cloud Models (3)

| Model ID | Family | Size | Key Env Var |
|----------|--------|------|-------------|
| `llama-3.3-70b-versatile` | Meta/Llama 3.3 | 70B | `GROQ_KEY_LLAMA70B` |
| `meta-llama/llama-4-scout-17b-16e-instruct` | Meta/Llama 4 | 17B | `GROQ_KEY_LLAMA4SCOUT` |
| `qwen/qwen3-32b` | Alibaba/Qwen | 32B | `GROQ_KEY_QWEN32B` |

#### Ollama Local Models (3)

| Model ID | Family | Size | Storage |
|----------|--------|------|---------|
| `mistral:7b` | Mistral AI | 7B | 4.4 GB |
| `gemma3:4b` | Google/Gemma | 4B | 3.3 GB |
| `deepseek-r1:7b` | DeepSeek | 7B | 4.7 GB |

### Added

- `rmbench/models/ollama_model.py` — OllamaModel class for local inference via Ollama REST API
- `rmbench/config.py` — `ModelBackend.OLLAMA` enum, `OLLAMA_MODELS` list, `backend_for()` routing function, `ALL_MODELS` export
- `rmbench/models/model_registry.py` — `_is_ollama()` detection, unified `get_model()` factory
- Per-model Groq API key support — `_MODEL_KEY_ENV` dict maps each model to its own key env var
- Context truncation in pipeline — each retrieved document capped at 600 characters to prevent oversized prompts
- `.env` — three separate `GROQ_KEY_*` slots (one per cloud model)

### Fixed

- **Critical**: `inject()` was called instead of `inject_docs()`, causing the attack context list to be stringified as `"['doc1', 'doc2']"` and iterated character-by-character, producing 10,000+ char prompts. Fixed to use `inject_docs()`.
- Groq 413/TPM rate limit errors — increased inter-request delay to 6s (10 req/min x 465 tokens = 4,650 TPM, under the 6,000 free-tier limit)
- Corporate TLS inspection proxy blocked Groq SDK — added `truststore` Windows CA store integration with `verify=False` fallback
- `UnicodeEncodeError` on Windows cp1252 console — replaced `→` (U+2192) with ASCII `->` in `run_benchmark.py`
- Double `_save_results()` call — removed duplicate from `BenchmarkPipeline.run()`; `run_benchmark.py` is now the sole save site
- `RMBenchConfig.__post_init__` hardcoded `ModelBackend.GROQ` — now calls `backend_for()` to correctly assign Ollama backend
- `benchmark/run_suite.py` — `choices=GROQ_MODELS` restriction removed to allow Ollama model names

### Removed

- `llama-3.1-8b-instant` — decommissioned from Groq
- `mixtral-8x7b-32768` — decommissioned from Groq
- `gemma2-9b-it` — decommissioned from Groq
- `qwen-qwq-32b` — decommissioned from Groq
- `deepseek-r1-distill-llama-70b` — decommissioned from Groq

## [0.1.1] - 2026-06-15

### Fixed

- Python 3.14 dataclass mutable default error — removed `@dataclass` from `Config` class
- Task type mismatch — `TASK_REGISTRY` keys (`"qa"`) did not match `TASK_TYPES` values (`"question_answering"`); added `_TASK_KEY_MAP` and `_TASK_DATASET_MAP`

## [0.1.0] - 2026-06-10

### Added

- Project structure and core framework
- Base classes: `BaseAttack`, `BaseDefense`, `BaseTask`, `BaseRetriever`
- 8 attack implementations (instruction_override, context_poisoning, goal_hijacking, tool_manipulation, authority_spoofing, memory_poisoning, multihop_injection, hidden_prompt_injection)
- 6 defense implementations (context_sanitization, injection_detection, trust_scoring, multi_agent_verification, constitutional_filtering, provenance_tracking)
- 6 task implementations (qa, code_generation, tool_use, planning, summarization, memory_evaluation)
- 6 evaluation metrics (ASR, CRI, GPS, Truthfulness, Tool Safety, Memory Integrity)
- FAISS-based retriever with `all-MiniLM-L6-v2` sentence-transformer embeddings
- Groq API model backend (`groq_model.py`)
- BenchmarkPipeline orchestrator
- CLI runners: `run_benchmark.py`, `benchmark/run.py`, `benchmark/run_suite.py`
- Task datasets (6 x 50 samples each)
- Attack templates (8 JSON files)
- Configuration files (YAML presets)
- Documentation (`docs/`, `README.md`, `ARCHITECTURE.md`, `QUICKSTART.md`)
- Test suite
- GitHub Actions CI
